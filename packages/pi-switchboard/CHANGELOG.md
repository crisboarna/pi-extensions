# @crisboarna/pi-switchboard

## 0.1.0

### Minor Changes

- [`45df244`](https://github.com/crisboarna/pi-extensions/commit/45df244b77af6454c773b23a6c1c0388c2b713f2) Thanks [@crisboarna](https://github.com/crisboarna)! - `pi-switchboard classifier detect` looks for LM Studio, Ollama and llama.cpp on this machine, lists the decision models each serves (and the chat models a llama.cpp server could serve as classifiers), tests the best one with pi-switchboard's three questions, and prints the config to paste. `/tier doctor` points to it when no classifier is configured or one does not answer.

- [`df409cb`](https://github.com/crisboarna/pi-extensions/commit/df409cbd55410518603a0941b62e09712b7ed873) Thanks [@crisboarna](https://github.com/crisboarna)! - `pi-switchboard classifier eval <baseUrl> <model>` asks a System One classifier (LM Studio, llama.cpp, Ollama, an MLX server or a hosted one) about 24 labelled requests and reports how many route to the expected tier, how many too low, and its latency, so you can compare models before choosing one.

- [`8adf558`](https://github.com/crisboarna/pi-extensions/commit/8adf558fc54df75542e76977aea9937104effcd7) Thanks [@crisboarna](https://github.com/crisboarna)! - `pi-switchboard classifier setup <lmstudio|ollama|llamacpp|llamacpp-chat>` gets a classifier server ready with the product's own commands: it checks the product is installed (it never installs it), shows the commands and asks before running them, waits for the server, tests the model, chooses its threshold on the 24 labelled requests, and adds it to `pi-switchboard.json` after showing the change. `llamacpp-chat` sets up a chat model that pi reads as a classifier, the best-measured route.

- [`d3eff20`](https://github.com/crisboarna/pi-extensions/commit/d3eff20548ce2971aefa2d5c9403a64fd7a0fbd4) Thanks [@crisboarna](https://github.com/crisboarna)! - Add `/tier try` (preview how a request would route, with typed answers when no classifier answers), `/tier doctor` (check the setup and say what to fix), `/tier tour` (a short walkthrough), a one-time notice when the extension starts without a config, and a bundled `pi-switchboard` skill that lets the agent explain and tune routing.

- [`78df25d`](https://github.com/crisboarna/pi-extensions/commit/78df25d8a0243e47bb5ff11793e08c2d7554cc58) Thanks [@crisboarna](https://github.com/crisboarna)! - `/tier eval [provider/model]` tests any classifier pi knows (a local server, a llama.cpp chat model, or a hosted one such as GPT-6 Luna, after a confirm) on the same 24 labelled requests as `pi-switchboard classifier eval`. Both now also replay the answers at several thresholds and suggest the one that suits the model, and the docs gain a page comparing measured models.

### Patch Changes

- [`30b4c01`](https://github.com/crisboarna/pi-extensions/commit/30b4c012f708094888300601c80d60fc1405ee78) Thanks [@crisboarna](https://github.com/crisboarna)! - A subagent child that fails over after an error (a usage limit, say) and then finishes is shown as done, not as failed.

- [`3467da8`](https://github.com/crisboarna/pi-extensions/commit/3467da8ecee805bb5984ce7a4204b1c8d58693c7) Thanks [@crisboarna](https://github.com/crisboarna)! - Classifier setup guides for LM Studio, llama.cpp (decision models and chat models), Ollama, MLX, hosted classifiers (GPT-6 Luna, Jev, Clef) and other servers (Unsloth, vLLM, LiteLLM), each with commands, a smoke test, the config and measured results. A classifier provider's `apiKey` written as `$NAME` is now read from the environment by the `pi-switchboard` command as well, and `classifier setup llamacpp-chat` starts llama-server in router mode and loads the model, which pi's `llama.cpp` provider needs.

- [`a50141f`](https://github.com/crisboarna/pi-extensions/commit/a50141f40a612e7a4ccc30a86593b4d9c93a4e52) Thanks [@crisboarna](https://github.com/crisboarna)! - The warning for a classifier pi does not list now names the real cause, at session start, at the first request and in `/tier validate`: pi's own provider has not listed it (is its server running with the model loaded?), its `classifierProviders` entry lacks it, or pi has no such provider. It no longer suggests credentials or `/login`, which never stop pi listing a classifier. - [`a1e5584`](https://github.com/crisboarna/pi-extensions/commit/a1e55841a9d91984ad34be73adce7123141a4972) Thanks [@crisboarna](https://github.com/crisboarna)! - `/tier doctor` no longer warns that the footer hides the tier when pi's footer or a pi-powerline-footer preset with extension statuses already shows it.

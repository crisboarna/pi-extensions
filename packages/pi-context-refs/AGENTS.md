# pi-context-refs

Save context refs and insert them from a picker as compact placeholders that expand to real content when the message is sent. These rules add to the repository `AGENTS.md`.

## Code map

- `src/index.ts` only wires; behaviour lives in named modules under `src/`.
- `src/core/` is pure: `trigger.ts` (which characters can be the Trigger, and the text typed after it), `picker.ts` (the picker's rows, sections, marks and what a pick inserts), `names.ts`, `text.ts` (stripping control characters from text that comes from outside), `file-content.ts` (what a File sends: caps, binary check, images, the closing line of a cut), `library.ts` (parse and validate a library file), `library-state.ts` (the session's copy: re-read, last good copy, each warning once), `resolve.ts` (precedence: Scoped Ref, Project library, Global, Built-in), `scope.ts` and `glob.ts` (does a scope match here), `confine.ts` (the Project library's rules), `tokens.ts`, `collapse.ts` (the tail Context-block parser, strict about attribute order), `segments.ts` (merges Placeholders into one editor segment), `expand.ts` (Expansion: inline kinds, File and Dynamic blocks, failures; it asks `env.approve` about each Project library command or URL Ref, one at a time, before anything runs), `approval.ts` (the definition of a command or URL Ref, its hash, the approvals file shape and its writer), `approval-list.ts` (the text of `/ref approvals`), `dynamic.ts` (a command's output as a block: limits, exit, cut, failures; the runner is injected), `url.ts` (a URL's body as a block, with the same limits and failure handling; the fetcher is injected), `builtins.ts` (the git Built-in Refs and the `builtins` setting), `context-block.ts` (the `<context-ref>` frame, text sanitizing, resend detection), `suggest-name.ts` (the name suggested for a saved Recent row), `recent.ts` (Recent refs: path resolution the way pi does it, what counts as a use, the in-memory set capped at 200, the paths in a row and a Placeholder, matching, the file-form guard).
- `src/pi/` is the glue: `picker.ts` (the autocomplete provider for the Trigger, added at `session_start` in the TUI), `overlay.ts` (the `alt+r` shortcut and the overlay loop: pick, or edit, remove and save and then open again) with `overlay-view.ts` (the overlay component: filter, sectioned list, preview) and `ref-save.ts` (saving a Recent row), `recent-source.ts` (feeds Recent refs from the branch at `session_start` and `session_tree`, and live from `tool_result` and `input`), `libraries.ts` (both libraries, trust and the Built-in Refs, for a send), `git-remotes.ts`, `editor.ts` (wraps the editor factory one tick after `session_start`, so it wraps the last editor installed; feature-checks `segment`; and gives the overlay the draft of the editor it installed), `input.ts` (the `input` handler, failures per mode, where warnings show), `exec.ts` (`pi.exec` as the command runner, the git work tree check, why a command could not start), `fetch.ts` (the GET: redirects by hand, a body read only up to the cap), `approvals.ts` (the approvals file, the Approval dialog at send), `running.ts` (the "running #x…" status and Esc, for commands and fetches), `transcript.ts` (the Markdown transformer: user messages only), `sent.ts` (`/ref sent`) with `text-viewer.ts` (its read-only dialog), `fs.ts`.
- `/ref` (list, add, edit, remove, approvals, approve, revoke, sent): `src/core/ref-command.ts` cuts the arguments (shell-style quoting, never a shell), `ref-edit.ts` builds and edits a Ref from `key=value` fields, `ref-list.ts` formats the list block and reads the settings, `ref-completions.ts` completes, `ref-relations.ts` words what a Ref shadows, `config-writer.ts` re-reads, changes and writes a library file; `src/pi/commands.ts` is the command, its dialogs and where its output goes, `ref-approvals.ts` (`approvals`, `approve`, `revoke`, and the one confirm that saves and approves a Project command or URL Ref), and `ref-run.ts` is one run's libraries, trust and place.
- `docs/adr/` holds the decisions and `docs/manual-checklist.md` the checks that need a person at a real terminal; `README.md` is the user's front door.
- `schema/pi-context-refs.schema.json` describes the library files and `schema/pi-context-refs-approvals.schema.json` the approvals file; `test/unit/schema.test.ts` and `approvals-schema.test.ts` keep them in step with the loaders.

## Status

- The package is built to the approved design (`DESIGN.md`). Its first release, 0.1.0, is staged: the `minor` changeset `.changeset/first-release-context-refs.md` says what a user gets, and the package stays unpublished at `0.0.0` until the maintainer merges the release pull request. After that, a change that alters what the package publishes needs a changeset of its own; a change to tests or docs only uses an empty one (`npm run changeset -- --empty`).
- Built: Path, File, Snippet and Dynamic Refs (a command or a URL) with the four git Built-in Refs; the Global library, and the Project library for trusted projects (confined to the project), Scoped Refs and precedence; typed `#name`, `#tag:<tag>` and `[ref:name]` expansion in every mode; File Refs cut at pi's read-tool caps, binary files refused, images attached; failures per mode (TUI restores the draft, RPC and print send a Failure note); Approvals of Project commands and URLs; the `#` picker with Recent refs; the `alt+r` overlay (filter, preview, save, edit, remove); the atomic Placeholder in the TUI editor; the transcript collapse and `/ref sent`; and `/ref` with `list`, `add`, `edit`, `remove`, `approvals`, `approve`, `revoke` and `sent`.
- Not yet done by a person: the manual TUI checklist in `docs/manual-checklist.md` (its boxes stay unticked until someone runs it in a real terminal) and the release decision. Do not tick a box without running the step.
- The pi behaviour the design relies on is proved and recorded in `DESIGN.md` section 16.1. Where pi differs from the first design (trust, the editor repaint, print-mode output), the design was amended; read it before changing anything, and `GLOSSARY.md` for the words to use.
- `/ref` knows `in=global`, `in=project` and (add, edit) `in=here`; edit and remove default to the library of the Visible Ref. `sent` shows the last user message on the session branch (a read-only dialog in the TUI, notify text in RPC, stderr in print and JSON). Its output goes to `ctx.ui.notify` where there is a UI and to stderr where there is none (print and JSON); the list block is the same text in both.
- Keep `README.md` in step with what a user sees; it follows `docs/conventions/readme.md` in the repository root.

## Tests

- `test/unit` (`npm test`), `test/integration` (`npm run test:integration`) and `test/smoke` (`npm run test:smoke`; CI runs it, and it loads `src/index.ts`, not the tarball). Coverage counts unit plus integration.
- Anything that runs real pi finds it through `PI_BIN`, else the repository's pinned `node_modules/.bin/pi`. The pty flows need `python3` and use `tools/media/run-in-pty.py` with xterm.js as the terminal.
- `test/support` holds the doubles: `stub-provider.ts` (answers locally and echoes the last user message it got, so a test asserts what the model received), `probe-extension.ts` (one scenario per run; test code, not package code), `pi-process.ts`, `pty-session.ts`, `editor-harness.ts` (a real pi-tui `Editor` with no terminal) and `segment-merge.ts` (the merge technique of ADR 0001, used by the contract test).
- `test/integration/input.test.ts` loads `src/index.ts` through jiti into the fake pi host (`test/support/fake-pi.ts`) with `PI_CODING_AGENT_DIR` in a temporary directory; the coverage run sets `CONTEXT_REFS_NATIVE_IMPORT=1` so V8 can map the source.
- `test/integration/overlay.test.ts` drives the `alt+r` overlay: the editor is built from the factory the package installs and given the shortcut the way pi's `CustomEditor` is, and the overlay component is fed key bytes; `test/smoke/overlay-tui.test.ts` does it in real pi in a pty.
- `test/integration/editor-segment-contract.test.ts` guards ADR 0001 against pi upgrades. Never weaken it to make an upgrade pass.
- `test/tui` (in `npm run test:integration` and coverage) runs real interactive pi in the test process on a virtual terminal (`test/support/virtual-terminal.ts`, started by `tui-session.ts`): keys go in as bytes, and the screen and the editor text come out. New keystroke checks go there, not in the pty smoke tests. Never send Ctrl+D on an empty editor, Ctrl+C twice or `/quit` in one: pi's shutdown ends in `process.exit`. `test/integration/interactive-mode-contract.test.ts` guards the assumption that pi draws into the terminal it is given. `virtual-terminal.ts` is a copy kept identical to the other packages' by `scripts/checks/copies.ts`. Each test file names the source files it covers in a `// covers: src/...` header; `scripts/checks/tui-coverage.ts` fails when a source file that calls `ui.custom`, `ui.select`, `ui.confirm`, `ui.input`, `ui.editor`, `setEditorComponent`, `registerShortcut`, `addAutocompleteProvider` or `onTerminalInput` is named in no header. `test/tui/neighbours-keys.test.ts` loads pi's own example extensions (`test/support/neighbours.ts`) before and after the package to test the shared places: the editor, `input` and the status line; `TuiSession` takes `before` and `extensions` for the order. `test/integration/editor-fuzz.test.ts` and `viewer-fuzz.test.ts` feed the editor and the `/ref sent` dialog random keys and text from a seeded generator (`FUZZ_SEED=<n>` replays a run).
- `test/coexist` (not in `npm run test:integration`) runs the package beside real third-party extensions that `npm run coexist` installs at the repository root; it skips without that script. Add an extension by pinning it in `scripts/coexist.json` and naming what one Backspace does to a Placeholder beside it in `NEIGHBOURS`.
- Before you write a `test/tui` test, read `docs/conventions/testing.md` in the repository root, and run `npm run soak` on it before you push.
- `test/integration/editor.test.ts` drives real pi-tui editors with key bytes through the package's decoration and the factory wrapper, including editor swaps; `test/smoke/placeholder-tui.test.ts` does the same in real pi in a pty.

## Rules from the design

- Refs are Path, File, Snippet or Dynamic; the Placeholder is `[ref:<name>]` and resolves by name at send (DESIGN.md sections 6 and 9).
- The Placeholder depends on one TS-private pi-tui method, `segment`, behind a feature check and a contract test (ADR 0001). The editor is wrapped one tick after `session_start` (ADR 0007); a test against the fake host waits a tick before it looks at the editor slot.
- A Project library loads only in a trusted project and is confined to it (ADR 0003); a Project Dynamic Ref runs only after an Approval of its definition hash, stored outside the project (ADR 0004).
- The Expansion is stored in the user message through the `input` event (ADR 0006); a Context block carries its `bytes` length.
- `src/core/` is pure and imports nothing from pi; commands and fetches are injected.
